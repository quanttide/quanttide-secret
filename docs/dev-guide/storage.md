# 存储技术选型

> 本文档记录量潮密码云（qtcloud-secret）的存储技术选型与决策依据。

## 1. 选型结论

量潮密码云的存储采用 **关系型数据库 + 对象存储分工协作** 的混合架构：

- **主存储：阿里云 OSS（对象存储）** —— 承担密文条目、附件等数据的存储与分发
- **关系层：阿里云 RDS PostgreSQL / PolarDB** —— 承担组织、团队、成员、权限、元数据、审计等关系型结构

两者不是竞争关系，而是各司其职：**OSS 管存储和分发，PG 管关系结构**。

## 2. 为什么选择阿里云 OSS 作为主存储

现代对象存储（以阿里云 OSS 为代表）具备以下原生能力，契合密码云场景：

| 能力 | 说明 |
|------|------|
| **原生加密** | 服务端加密（SSE-OSS / SSE-KMS），开箱即用；SSE-OSS 由 OSS 托管密钥、自动轮换、免费 |
| **分发方便** | presigned URL 直传/直下，客户端直连 OSS 不经应用服务器；配合 CDN 加速、分片上传、断点续传，移动端与 Web 端体验好 |
| **成本与规模** | 按量计费，生命周期策略自动降冷/归档，海量数据扩展无压力 |
| **高可用** | 跨可用区冗余、同城/异地容灾能力由云厂商保障 |

## 3. 为什么保留 PG 作为关系层

对象存储不提供事务、JOIN、约束、服务端过滤等能力，而密码云的核心业务结构是高度关系型的：

- 组织 / 团队 / 成员 / 角色 / 权限（RBAC 关联建模）
- 保险库（Vault）与条目元数据（分类、标签、检索）
- 审计日志（追加 + 按时间/操作者查询）

这些数据需要事务（创建保险库 + 授权成员需原子）、外键约束、复杂查询（"列出团队 A 中我可见的条目"），必须由关系型数据库承载。

> 参考：1Password 的服务端同样具备账号/保险库/权限的元数据层，密文 blob 才走对象存储。

## 4. 数据分层

| 数据 | 存储 | 理由 |
|------|------|------|
| 密文条目（客户端加密后的 blob） | 阿里云 OSS | 存储与分发主体，presigned URL 直传直下 |
| 附件 / 大文件 | 阿里云 OSS | 体积、版本、生命周期、成本优势 |
| 组织/团队/成员/角色/权限 | PG | 关系型建模、事务、约束 |
| 条目元数据（分类/标签/检索） | PG | 需要查询与过滤 |
| 审计日志 | PG（起步） | 追加 + 查询顺手；量大后拆分冷归档 |

> **私有化部署考量**：面向私有化客户时，对象存储层采用 S3 兼容协议实现（如 MinIO），代码仅依赖 OSS/S3 API，不绑定具体云厂商。

## 5. 双重加密方案

采用 **客户端加密 + 服务端加密** 双重加密，两层防的是完全不同的攻击面，叠加成本很低：

| 层 | 实现 | 防御的攻击面 |
|----|------|-------------|
| **第 1 层：客户端加密（零知识）** | 明文只在客户端加密，密文上传；保险库密钥（DEK）用成员公钥包裹分发 | 应用漏洞、云厂商/内部人员、被取证 |
| **第 2 层：服务端加密（OSS SSE-OSS）** | 密文落盘时 OSS 用托管密钥再加密一次 | 物理介质泄露、备份/快照泄露 |

单靠 SSE-OSS：信任模型是"信任云厂商"；单靠客户端加密：密文裸存于 OSS 磁盘，备份泄露即密文裸奔。**两层叠加后，任意一层失守都不影响另一层**——即使云厂商被攻破或配合取证，也无法还原明文。

> 服务端加密成本说明：SSE-OSS 免费；SSE-KMS 依赖的 KMS 共享版已 EOFS/EOS 停服，新购 KMS 密钥只能购买专属密钥管理实例（软件实例 2,499 元/月起），当前阶段不引入，用 SSE-OSS 即可。

### 客户端加密的工程要点

- 每个保险库一把**保险库密钥（DEK）**，用成员公钥包裹后存服务端（信封加密）
- **成员加入**：用新成员公钥重新包裹 DEK
- **成员离开**：轮换 DEK 并重加密该保险库条目
- 主密码找回依赖恢复码（Emergency Kit）机制
- 算法采用 AES-256-GCM（硬件加速，性能影响可忽略）

## 6. 整体架构

```
客户端 ──AES-256-GCM 加密──> 密文条目/附件 ──presigned URL 直传──> 阿里云 OSS（SSE-OSS 二次加密）
客户端 ──API──> 应用服务 ──> 阿里云 RDS PostgreSQL / PolarDB（组织/团队/成员/RBAC/元数据/审计）
密钥层：OSS 托管服务端加密密钥（SSE-OSS 自动轮换）+ 客户端保险库密钥（公钥包裹分发）
```

一句话总结：**OSS 管存储和分发，PG 管关系结构，客户端管零知识，OSS 管服务端加密——四层各司其职，双重加密是免费的信任升级。**

## 7. 演进路径

1. **起步**：OSS + PG 双存储到位，密文条目与附件均走 OSS
2. **规模化**：审计日志量大后从 PG 拆分，冷归档至 OSS 生命周期策略
3. **私有化**：对象存储层切换为 S3 兼容实现（MinIO），其余架构不变
