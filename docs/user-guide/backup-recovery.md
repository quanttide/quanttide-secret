# 备份与恢复指南

> 面向用户的使用说明。技术原理见 [dev-guide/security.md](../dev-guide/security.md)。

## 1. 为什么你需要备份

量潮密码云采用**零知识加密**设计：你的密码内容在设备上加密后才上传，我们（服务端）也读不到你的数据。

这带来一个推论：**解密钥匙只存在于你手中，没有人能帮你找回**。所以备份不是可选项，而是使用本产品的基本义务——不备份，丢钥匙 = 丢数据。

## 2. 备份什么：恢复码（Emergency Kit）

需要备份的**不是主密码**（主密码记在脑子里，写下来反而危险），而是一份 **Emergency Kit**：

```
Emergency Kit（紧急恢复套件）
├── 账户信息：用户名
├── 恢复码：一串随机字符（真正的备份对象）
└── 使用说明
```

- **恢复码**与主密码一起用于解密你的数据
- 主密码泄露但无恢复码 → 攻击者无法解密你的数据
- 主密码忘记但有恢复码 → 你可以恢复
- **两者都丢 → 数据永久丢失，无法找回**

## 3. 如何保存 Emergency Kit

注册时系统会引导你生成 Emergency Kit，请选择一种方式妥善保存：

| 方式 | 推荐度 | 说明 |
|------|--------|------|
| **打印纸质，放入保险柜/钱包** | ⭐ 最推荐 | 物理隔离、不联网，最抗攻击 |
| **加密文件，存放在另一处** | 推荐 | 文件本身需另一个密码保护，注意别和主密码放在一起 |
| **存入另一个密码管理器** | 可行 | 鸡蛋放另一个篮子，注意两个服务不能同时不可用 |

## 4. 忘记主密码怎么办

1. 打开登录页，选择"使用恢复码恢复"
2. 输入你的**恢复码**
3. 设置**新的主密码**（系统会校验强度）
4. 数据重新加密，恢复完成

> 整个恢复过程在你的设备本地完成，不需要也不应把恢复码提供给任何人，包括客服。

## 5. 团队版：受托恢复（Trusted Contacts）

个人版只有 Emergency Kit 一条路（备份给"一张纸"）。团队版提供**受托恢复**：把恢复能力备份给"一群人"——你的数据恢复码会被拆成几份碎片，分给几位可信同事保管，凑够人数才能恢复。

> 生活类比：银行保险柜的"双人开锁"——两把钥匙分属两个人，必须两人同时在场才能打开。受托恢复是它的推广版。

**阈值机制（Shamir 秘密分享）**：

| 参数 | 含义 | 例子 |
|------|------|------|
| n（成员数） | 一共分给几个人 | 5 位同事 |
| k（阈值） | 凑齐几个人才够恢复 | 3 人（3/5） |

- 你的恢复码拆成 **n 份碎片**，每人拿 1 份
- 任意 **k 人**凑齐 → 重构恢复码 → 恢复数据
- 少于 **k 人** → 数学上什么都得不到（碎片毫无用处）
- 数学保证：少于 k 份碎片，即使全部拿到也无法还原恢复码

**使用流程**：

```
【设置】你选 5 位可信同事，设阈值 3 → 恢复码拆成 5 份分别发给同事保管
【平时】碎片静静躺在同事设备里，无需你操作
【忘记主密码时】向任意 3 位同事发起恢复请求 → 同事点"同意" → 碎片汇聚重构 → 设置新主密码
```

**安全特性**：

- 服务端只转发加密碎片，**永远看不到完整恢复码**——零知识依然成立
- 任何单个成员只有碎片，不知道你的恢复码；服务端被攻破也要凑齐多份碎片才能还原
- 碎片在同事手里而不是服务器里：恢复能力属于"人"，不属于"系统"

**注意事项**：

- 选择真正信任的人，阈值设高一点（如 3/5 而非 2/3），防止合谋
- 同事离职时支持重新分发碎片（剔除后重新拆分发）
- 每次恢复需你本人配合，并有审计记录

## 6. 数据本身的备份（导出）

恢复码备份的是"钥匙"，**数据本身**建议定期导出备份：

- **导出**：客户端提供"导出加密备份文件"功能（服务端备份导出接口返回全部密文信封，客户端拉取保存），导出的文件包含你的全部数据，用你的主密码保护
- **用途**：换设备、迁移、极端情况下的最终保险
- **注意**：导出文件等同你的数据本身，请像保管钥匙一样保管它

服务端侧，你的数据还有 OSS 版本控制兜底（误删/误写可回滚），但这**不能替代**你自己的备份——服务端备份保护的是"操作失误"，你的备份保护的是"钥匙丢失"。

## 7. 安全提醒

- ❌ 不要把恢复码与主密码**放在同一处**（如同一张纸条、同一个云笔记）
- ❌ 不要将恢复码**截图存在手机相册**或发到聊天工具
- ✅ 恢复码与主密码分开保管，各防一种风险（主密码被窃取 / 主密码被忘记）
- ✅ 定期检查 Emergency Kit 是否还在（建议每半年一次）

## 8. 常见问题

**Q：可以把恢复码告诉客服帮我恢复吗？**
不能。客服没有你的主密码与恢复码，也无法重置——这是零知识设计的必然结果。任何索要恢复码的"客服"都是诈骗。

**Q：换了手机怎么办？**
在新设备登录（输入用户名 + 主密码 + 恢复码），数据自动同步并解密。若只记得部分信息，用 Emergency Kit 恢复流程。

**Q：团队成员离职了，他的数据怎么办？**
若你已启用受托恢复，向其他可信成员发起恢复即可；未启用时请确保每位成员都保存了自己的 Emergency Kit。团队版恢复流程（管理员协助）即将上线，届时可查看相应说明。
